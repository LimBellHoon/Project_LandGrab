# 로그라이트 전면 재작성 — 구현 스펙 각색 (260928)

> **상태: 설계 문서. 코드 아직 미착수.** 사용자가 준 "땅따먹기 로그라이트 — 구현 스펙 v1.0"(이하 **원본 스펙**)을
> 이 리포의 실제 클래스·CSV·컨벤션에 맞게 각색한 문서다. 원본 스펙 전문은 이 문서에 다시 옮겨 적지 않았다 —
> "무엇이 바뀌는지"와 "이 리포에서는 어느 클래스/파일이 그 자리인지"만 적는다. 구현할 때는 원본 스펙과 이 문서를
> 같이 펴 놓고 볼 것.

## 0. 확정된 방향 (260928, 사용자 확인)

**전면 재작성.** 원본 스펙대로 이동·카메라·점령·몬스터 체력을 다시 짠다 — 지금 있는 연속 다각형 이동(2-3, 2-22),
HP 풀(2-14), 올가미 점령 규칙(2-3)을 전부 걷어낸다. 단 아래 세 가지는 원본 스펙에서 벗어난다.

| 항목 | 원본 스펙 | 이 리포의 결정 |
|---|---|---|
| 카메라 | §1 "세로 화면 한 장에 전체 표시, 카메라 고정" | **기존 카메라 추적을 유지한다**(2-10, `CCameraFitter`/`CGameManager.Tick_Camera`). 격자가 60x100으로 커지므로 오히려 추적이 더 필요하다 — "맵이 커질수록 이동속도 강화가 값어치를 갖는다"는 기존 설계 의도(2-10)를 그대로 지킨다 |
| 가둬 잡기 | 명시 없음(그로기/기절 체계만 서술) | **점령으로 몬스터를 가두면 그로기 상태와 무관하게 즉시 죽는다**(기존 2-3 `Kill_EnemiesInOwned` 그대로 유지). 그로기·기절은 "몸으로 부딪히거나 지나가지 못하게" 막는 상시 압박이고, 점령은 여전히 최종 공격 수단이다 — 두 체계가 서로 다른 층위에서 같이 간다 |
| 웨이브 제한 시간 | §1 "목표 시간"(스테이지 테이블), 시간 소진 시 서술 없음(암묵적으로 실패 없음처럼 읽힘) | **명시적으로 확인** — 제한 시간 소진으로 인한 실패(`STAGE_STATE.FAIL`)를 없앤다. 목표 시간은 **오직 별 등급**에만 쓴다(§5 참고) |

카드 30종(원본 스펙 §5, §9)은 **기존 사냥형 8종 + 회피형 7종(`Docs/Design_Card_Pool.md`)을 전량 교체**한다.
"쓸 만한 것만 남기자"는 사용자 확인에 따라, 이번 각색에서 겹치는 개념은 새 카드 쪽에 흡수시키고
`CardInfo.csv`는 새 30종(K/M/G/F)만 남긴다 — 자세한 매핑은 §6 참고.

## 1. 걸리는 기존 시스템 — 무엇이 없어지는가

전면 재작성이 실제로 건드리는 자리를 미리 적어 둔다. 구현 중 "이것도 지워야 하나" 고민을 줄이기 위함이다.

| 파일/클래스 | 지금 하는 일 | 재작성 후 |
|---|---|---|
| `CMoveHandler` | 연속 좌표 + 다각형 경계 미끄러짐(2-3) | ✅ 260928_**칸 중심 스냅 이동으로 다시 썼다**(§2). 거의 새로 쓰는 수준이었다. 8방향 · 나선형은 대각선 입력 자체를 막아 보류 상태로 남겼다 |
| `CTerritoryGrid` | 다각형(`RINGS`) + Clipper2 불리언 연산, 올가미 규칙(260923) | ✅ 260928_**칸 배열 기반으로 되돌렸다**(§3). Clipper2 참조는 끊었다(파일은 안 지움). 도화선은 골격만 유지(수치는 태스크 #18), 굴절은 아직 미착수(§3-3, 태스크 #19) |
| `CGridRenderer` / `CTrailMesh_Utility` | 마스크 텍스처 + 띠 메시(2-3, 2-3-1) | ✅ 260928_마스크 래스터라이즈(`Refresh_All`)는 칸 그대로 뚫는 방식으로 단순해졌다(서브픽셀 안티앨리어싱 제거). 트레일 메시는 `TRAIL_PIECES` API가 그대로라 `CTrailMesh_Utility`를 손대지 않고 재사용했다 |
| `CEnemy` / `EnemyInfo.csv`의 `iHp`/`iAttack` | HP 풀 기반 전투(2-14, 2-6) | **몬스터 HP를 없애고 그로기 게이지로 교체**(§4). `iAttack`은 유지하되 의미가 "그로기 지급량"이 아니라 여전히 "몸 충돌 피해"로 남는다(원본 스펙 §2.1은 몸 충돌 피해를 고정 HP -1로 서술 — 몬스터별 차등을 유지할지는 §4 참고) |
| `CPlayer.Damage` 계열(2-14, 사냥형/회피형 카드) | 가변 피해 + 보호막 중첩 + 회피 확률 + 넉백 | **원본 스펙 §2.1 그대로 고정 피해 1 + 무적 1.0초**로 단순화. 사냥형/회피형 카드가 걸어 두던 `BODY_DAMAGE_SCALE`·`KNOCKBACK_SCALE`·`THORN_DAMAGE` 등은 카드째 교체되므로 함께 정리한다(§6) |
| `CStage_Manager.Tick`의 `m_fRemainTime` 소진 → `FAIL` | 웨이브 제한 시간 초과 시 실패 | **삭제.** 시간은 계속 재되(별 등급용), 실패 조건에서 뺀다(§5) |
| 도화선(2-14-1, `Ignite_Fuse`/`Tick_Fuse`/`Set_Burn`) | 몸이 선에 닿으면 발화, 트레일 끝(플레이어)까지 타들어온다 | **원본 스펙 §2.2로 수치만 갱신**(전파 속도 4.2칸/초, 최소 유예 2.0초, 전파 방향이 "내 땅 쪽부터"). 구조(`CStage_Manager`가 타이밍을 재고 `CTerritoryGrid`가 탄 구간만 표시)는 그대로 재사용 가능 |
| 캐릭터별 이동 방식(2-22, `MOVE_STYLE.EIGHT_WAY`/`SPIRAL`) | 캐릭터마다 다른 이동 | 원본 스펙은 4방향 고정만 서술한다. **이번 재작성 범위에서는 4방향만 만들고, 8방향·나선형은 보류**로 남긴다(코드를 지우지는 않되 `CInputHandler`/`CMoveHandler`가 이 스타일들을 부르지 않게 된다) — 캐릭터 시스템 자체(스킨·스탯 배율, 2-17)를 없애자는 이야기는 없었으므로 그 부분은 유지 |
| 로비 장착 스킬(2-11, `SkillInfo.csv`: WARP/SHIELD/DASH/SLOW/SEAL/RUSH) | 스테이지 진입 전 장착하는 액티브 하나 | 원본 스펙은 이 계층을 언급하지 않는다. **당장은 그대로 둔다** — WARP·RUSH 둘 다 "지금 방향으로 N칸"이라 칸 기반 이동으로 돌아가면 오히려 구현이 더 쉬워진다(칸 수만큼 `Get_NextCell`을 반복하면 된다). 단 `CSkillEffect_Shield`의 무적 시간, `CSkillEffect_Slow`의 감속 대상(HP 없는 몬스터에게 감속은 여전히 의미가 있다) 정도만 재검토가 필요하다 |
| 런 스킬(2-11-1~2-11-3, `RunSkillInfo.csv`) | 판 안 3지선다로 얻는 뱀서라이크형 스킬 | 원본 스펙의 3지선다(§4)는 **오직 카드(K/M/G/F)만** 뽑는다 — 런 스킬과 섞어 뽑는 기존 `CPickOption_Utility.Pick`(2-10-1)이 이제 필요 없다. **런 스킬 자체를 없앨지, 카드 30종과 통합할지는 아직 결정 안 됨** — 겹치는 개념이 많다(월보=원본 스펙에 없음, 회전탄/몽둥이=원본 스펙에 없음, 마비탄=K01 감전 선과 결이 비슷함). §6 끝에 후보로만 적어 둔다 |
| 웨이브/보상 이미지 스택(2-5, `strLayerTex`) | 웨이브를 깰 때마다 가림막이 벗겨져 스킨 그림이 드러난다 | **건드리지 않는다.** 이 리포의 첫 줄 자체가 "뒤에 깔린 보상 이미지를 점령해서 드러내는 것이 핵심 재미"다 — 원본 스펙은 이 개념을 언급하지 않지만 없애자는 요청도 없었다. **원본 스펙의 "스테이지 1~10, 스테이지당 목표 점유율 하나"를 이 리포의 "웨이브"에 그대로 매핑한다** — 스테이지 테이블(§7)의 각 행이 `MapInfo.csv`의 웨이브 한 줄이 된다. 이 가정이 틀렸으면(예: 맵 자체를 스테이지 10개로 늘리는 뜻이었다면) 구현 전에 확인이 필요하다 |

## 2. 이동 — 칸 중심 스냅 (원본 스펙 §1)

`CMoveHandler`를 아래 상태 기계로 다시 짠다. 좌표는 다시 **칸 정수 좌표**(`Vector2Int`) 기준이고,
칸 사이 보간만 연속값으로 둔다(옛 260901~260922 시절 `CMoveHandler`와 같은 뼈대 — git 이력에서 이 시절
커밋을 참고하면 뼈대를 아예 새로 짤 필요는 없을 수 있다).

```
상태: 칸 위에 정지 / 칸 사이 이동 중
입력: 조이스틱 드래그 벡터 → 4방향 중 하나(±10° 히스테리시스) 또는 NONE
```

- **선예약**: 칸 중앙 도달 전 입력은 큐에 쌓아 뒀다가 중앙에서 실행. 이미 `CPlayer.Request_Skill`의
  0.25초 버퍼(2-11)와 같은 패턴이라 그대로 본뜨면 된다
- **후보정(30%)**: 중앙을 지난 뒤라도 칸의 30% 이내면 중앙으로 스냅 후 전환 처리 — 새 로직
- **조이스틱 파라미터**(데드존 11px, 재설정 반경 40px)는 **고정 픽셀이 아니라 기존처럼 화면 높이 비율로
  환산해 적용한다**(2-6-1, "픽셀이 아니라 화면 높이 비율이라 해상도가 달라도 같은 느낌"). 원본 스펙의 px 값은
  기준 해상도(1080x1920, 2-10)에서 화면 높이 비로 환산해 상수를 정한다(11/1920 ≈ 0.0057, 40/1920 ≈ 0.0208)
- **손 뗐을 때**: 내 땅 = 정지, 선 긋는 중 = 마지막 방향 유지(기존 2-3의 260921 결정과 반대 방향인데,
  원본 스펙이 그렇게 못박았으므로 **이번엔 스펙을 따른다** — "역주행 입력만 무시하고 나머지는 계속 진행")
- **안전 귀환 버튼**: 선 긋는 중에만 노출. `CTerritoryGrid`에서 "가장 가까운 내 땅 칸까지의 최단 경로"를
  BFS로 구해 자동 이동시킨다(그리드가 다시 칸 배열이 되므로 BFS가 자연스럽다 — 다각형 시절엔 이런 걸
  붙이기 어려웠다). 도화선이 타는 중이면 불의 반대 방향으로 경로를 다시 구한다
- **닫기 자석**(선 끝이 내 땅 1칸 이내면 자동 연결)은 **시스템 기본값으로 둔다** — 카드가 아니라
  `CTerritoryGrid.Try_Close`가 항상 확인하는 조건이다(사용자 확인: "자석 닫기는 카드에서 빼고 기본 시스템 값으로")

## 3. 점령 · 도화선 · 굴절

### 3-1. 칸 기반 점령으로 회귀
`CTerritoryGrid.RINGS`(다각형)를 걷어내고 `CELL_STATE[,]` 배열 + 플러드필로 되돌린다(2-3 이전, 260923에
뒤집기 전의 방식과 같은 결). Clipper2(`Assets/Plugins/Clipper2`)는 더 이상 쓰지 않는다 — 지우지는 말고
당장은 참조만 끊는다(나중에 필요해질 수 있어 리포에서 완전히 제거하는 것은 별도 확인 후).

### 3-2. 도화선 (원본 스펙 §2.2)
기존 도화선 골격(`Ignite_Fuse`/`Tick_Fuse`, 2-14-1)을 그대로 쓰되 수치와 방향을 스펙에 맞춘다.

| 항목 | 기존 | 원본 스펙 |
|---|---|---|
| 전파 속도 | 3칸/초 | **4.2칸/초**(기본 이동속도 6.0의 70%) |
| 전파 방향 | 발화점 → 트레일 끝(플레이어) | 동일(스펙 §2.2 "내 땅 쪽부터 플레이어 쪽으로"는 "발화점에서 플레이어를 향해"와 같은 뜻으로 읽었다) |
| 최소 유예 | 없음 | **발화 시 플레이어-불 최소 2.0초 거리 보장** — 짧은 선에서 즉시 따라잡히지 않게 발화 시점에 거리를 미리 확보 |
| 따라잡힘 결과 | 선 소실 + `Damage(fuseDamage, true)` | 선 소실 + **고정 HP -1**(가변 피해 폐지, §1) |

### 3-3. 굴절 (원본 스펙 §2.3, G08 전용)
칸 기반으로 돌아가면 원본 스펙의 "정점 우회로 삽입"보다 단순하게 구현할 수 있다 — **적이 부딪힌 칸을
진행 방향으로 depth칸만큼 미는 대신, 트레일 칸 배열에서 그 칸 자리에 "ㄷ자" 우회 칸들을 끼워 넣는다.**
유효성 검사(자기 선·맵 경계·기존 내 땅과 겹치지 않는가)도 칸 단위 비교라 다각형 교차 검사보다 훨씬 쌉다.
굴절이 불가능하면(칸 밀 자리가 없음) 그대로 도화선으로 폴백 — 스펙의 폴백 규칙 그대로.

## 4. 몬스터 — 그로기 & 기절 (원본 스펙 §3)

`EnemyInfo.csv`에 `iHp` 대신(또는 병행) **`iGroggyMax`**(그로기 총량)를 추가한다. `CEnemy`는 더 이상
죽지 않는다 — `Damage(int)`가 그로기를 깎는 쪽으로 바뀌고, 가득 차면 기절(`STUN`) 상태에 들어간다.

```
CEnemy.m_fGroggy          0 ~ iGroggyMax
CEnemy.Add_Groggy(fAmount)   기존 CImpactHandler의 STUN 엔트리와 자연스럽게 합칠 수 있다(2-15) —
                              "기절"이라는 결과 자체는 이미 CImpactHandler.IS_STUNNED가 내고 있었다
CEnemy.Tick                  자연 감소(초당 -2%) · 내성(기절마다 다음 요구량 +25%, 판당 누적) 적용
```

- **판당 기절 상한 5회, 초과 시 내성 증가폭 +100%**는 `CStage_Manager`가 몬스터별로 카운트를 들고 있어야
  한다(웨이브가 아니라 판 전체 — `Release()`에서만 리셋, `Enter_Wave`에서는 유지) — 기존 "몬스터는 웨이브가
  넘어가도 거두지 않는다"(2-5) 원칙과 자연스럽게 맞는다
- **몸 충돌 피해**는 원본 스펙 §2.1대로 고정 HP -1이지만, `EnemyInfo.csv`의 `iAttack`을 그로기 지급량
  으로 재활용할지, 완전히 없앨지는 확정 필요 — 우선 "몸 충돌은 항상 고정 1피해, `iAttack`은 그로기 지급용
  으로 의미를 바꾼다" 쪽을 제안한다(같은 숫자를 두 번 정의하지 않는다는 1-1 원칙에 맞는다)
- 상태이상 확장(빙결·속박·둔화·넉백)은 `CImpactHandler`가 이미 갖고 있는 SLOW/STUN/KNOCKBACK 틀을
  그대로 확장하면 된다(2-15) — "속박"(이동 불가·행동 가능)만 새 엔트리 종류가 필요하다

## 5. 웨이브 제한 시간 → 별 등급으로 (사용자 확정 사항)

`CStage_Manager.Tick`의 `m_fRemainTime <= 0f → Set_State(FAIL)` 분기를 삭제한다. 대신:

```
Enter_Wave에서 m_fRemainTime = cWave.fTimeLimit  (이제 "제한"이 아니라 "목표 시간"의 의미로 읽는다)
웨이브 클리어 순간 fElapsed = cWave.fTimeLimit - m_fRemainTime  (음수면 0으로 클램프하지 않고 그대로 초과 기록)
Calc_TimeStar(fElapsed, fTimeLimit):
    fElapsed <= fTimeLimit         → 3성
    fElapsed <= fTimeLimit * 1.5   → 2성
    그 외(제한 시간 넘게 걸렸어도 클리어는 클리어)  → 1성
```

- 시간 초과로 죽지 않으므로 **아무리 오래 걸려도 클리어는 클리어**다. 이 리포의 기존 `STAR`(=완료한 웨이브 수,
  맵 해금에 쓰임, 2-7/2-17)와는 **다른 값**이라 이름을 구분해야 한다 — 가칭 `TIME_STAR`. 맵 해금 순서(2-7)는
  기존 `STAR`(웨이브 수) 그대로 쓰고, `TIME_STAR`는 스테이지 선택 화면에 별 아이콘(☆☆☆)으로만 보여주는
  표시용 지표로 시작하는 것을 제안한다 — 보상과 연결할지는 기획 확인 필요
- `CProtoTest`에 이미 있는 시간 무관 테스트들은 영향 없음. 시간 초과로 실패하던 걸 테스트하던 코드가
  있다면(`CProtoTest.Test_...TimeLimit` 류) 그 부분만 제거·수정

## 6. 카드 시스템 — CardInfo.csv 전량 교체

`Client_Enum.CARD_TYPE`의 기존 값(`SHIELD`~`DODGE_FREE_HIT`, 이번 세션에 넣은 것 포함)을 전부 지우고
원본 스펙 §9의 30종으로 새로 채운다. 매핑 원칙:

- **`eType` 이름은 스펙의 ID를 그대로 쓴다**(`K01_ELECTRIC_TRAIL`처럼 ID+영문명 조합, 또는 `K01`을 그대로
  enum 값으로 써도 된다 — 이 리포는 이미 `HUNT_THORN`처럼 의미 있는 영문명을 쓰는 컨벤션이라 **`K01_ELECTRIC_LINE`
  식으로 접두사(K/M/G/F)+의미명**을 권장한다). `strName`에 원본 한글명을 그대로 적는다
- **`family`(계열)는 새 열이 필요하다** — 지금 `eTheme`(COMBAT/MOVE)은 2종뿐인데 스펙은 4계열(제어/기동/
  수호/도화선)이다. `PICK_THEME`를 4종으로 늘리거나(카드 색도 4색이 되어야 한다, 2-10-1 카드 UI 참고) 새
  enum `CARD_FAMILY`를 별도로 두고 색은 `family`에서 파생시킬지 결정 필요 — **`PICK_THEME`를 4종으로
  늘리는 쪽을 제안한다**(색 파생 로직이 하나로 유지된다)
- **레벨(Lv.1~3, 중복 선택 시 성장)**은 지금 카드 시스템에 없는 개념이다(기존 카드는 1회성 즉시효과 또는
  단순 누적이었다). `RunSkillInfo.csv`/`CRunSkillHandler`가 이미 "레벨별 수치 + 판마다 초기화 + 중복 선택 시
  레벨업" 구조를 갖고 있으므로(2-11-1), **카드 시스템을 아예 런 스킬 핸들러 구조로 흡수 통합하는 것을
